# Writing .csx macros for the Macros extension

A macro is a Roslyn C# script (`.csx` file) that the Macros for Visual Studio extension runs in-process. It has top-level `await`, an injected set of globals (`DTE`, `VS`, `Context`, `Trigger`), and a vocabulary of async helper verbs. Macros live in one of two scopes — global (`%APPDATA%\Macros\<name>.csx`) or repo (`<solution>\.vs\Macros\<name>.csx`) — and are picked up by a file-watcher on save, so editing a `.csx` in Visual Studio takes effect immediately.

This skill is the hub. For deeper sub-topics:

- Triggers (`// @trigger`, event subscriptions, command interception, filters): see [`macro-triggers`](../macro-triggers/SKILL.md).
- The DTE automation surface (`DTE.ActiveDocument`, `EnvDTE.TextSelection`, `DTE.Solution`, `DTE.Debugger`): see [`macro-dte-api`](../macro-dte-api/SKILL.md).
- The Community.VisualStudio.Toolkit `VS` facade (status bar, message boxes, info bars, output pane, document service): see [`macro-toolkit-api`](../macro-toolkit-api/SKILL.md).
- Diagnosing failures, runtime vs IntelliSense, the `Log` static class, error surfaces: see [`macro-debugging`](../macro-debugging/SKILL.md).

## Canonical macro shape

```csharp
// Macro: My Macro
// Recorded: 2026-05-02T17:10:39Z
// Generated by Macros — edit freely.

// IntelliSense + script globals come from this shim (auto-generated by the Macros VSIX).
#load ".intellisense/Macros.Intellisense.csx"
using Community.VisualStudio.Toolkit;
using static Macros.Engine.Scripting.Helpers;

await TypeAsync("Hello from a macro");
await ExecuteCommandAsync("Edit.FormatDocument");
```

Three rules anchor the file:

1. The header comment block stays at the top. Any `// @trigger` lines (covered by [`macro-triggers`](../macro-triggers/SKILL.md)) live inside this block, *before* `#load`.
2. The `#load ".intellisense/Macros.Intellisense.csx"` directive is preserved — it provides the editor-time IntelliSense for `DTE`, `VS`, `Context`, `Trigger`, and the helper verbs. The macro player ignores this directive at runtime; never delete it to "fix" a runtime issue.
3. Executable code follows the directive. No class declarations, no `Main()`. Top-level `await` works.

## Helper verbs (preferred vocabulary)

Available without imports — the IntelliSense shim adds `using static Macros.Engine.Scripting.Helpers;` for you.

| Verb | Purpose | Notes |
|---|---|---|
| `TypeAsync(string text)` | Insert text at the caret as if typed. | Most-used helper. |
| `MoveCaretAsync(int line, int col)` | Move caret to a 1-based position. | |
| `SelectAsync(int sl, int sc, int el, int ec)` | Select a span; coordinates 1-based. | |
| `ExecuteCommandAsync(string name, string args = "")` | Invoke a named VS command. | E.g. `Edit.FormatDocument`. |
| `RunCommandAsync(Guid group, uint id, object? args = null)` | Invoke a command by GUID + ID. | For commands without a public name. |
| `OpenFileAsync(string path)` | Open a file in the editor. | Brings to foreground if already open. |
| `WaitAsync(int ms)` | Pause the script. | Use sparingly; prefer state checks. |
| `PromptAsync(string label, string defaultValue = "")` | Show a VS input dialog and return the user's text. | Returns `defaultValue` on cancel. |
| `RunMacroAsync(string name)` | Run another saved macro inline (repo-wins lookup). | Cycles + depth >3 throw `InvalidOperationException`. |
| `InsertSnippetAsync(string prefix)` | Type a snippet shortcut and ask VS to expand it. | Caret must be in a snippet-aware editor. |

Prefer helpers first. Drop to `DTE` or `VS` only when the helper vocabulary doesn't cover what you need.

## Script globals

The macro player injects four globals before running the script:

| Global | Type | Purpose |
|---|---|---|
| `DTE` | `EnvDTE80.DTE2` | Visual Studio's classic automation root. See [`macro-dte-api`](../macro-dte-api/SKILL.md). |
| `VS` | static | Community.VisualStudio.Toolkit facade. See [`macro-toolkit-api`](../macro-toolkit-api/SKILL.md). |
| `Context` | `IMacroContext` | Macro name (`Context.MacroName`) + cancellation token (`Context.Cancellation`). |
| `Trigger` | `IMacroTrigger` | Why the macro ran. `Trigger.IsManual`, `Trigger.Payload`, `Trigger.CancelCommand()`. |

```csharp
if (DTE.ActiveDocument != null)
{
    await VS.StatusBar.ShowMessageAsync($"Running {Context.MacroName}");
}
```

## Logging to the Macros Output pane

For non-blocking diagnostics, use the `Log` static class. Each line is prefixed with `[HH:mm:ss SEVERITY MacroName]` so output from multiple macros stays attributable.

```csharp
await Log.InfoAsync("Starting cleanup pass");
await Log.WarnAsync($"Skipped {skipCount} files");
await Log.ErrorAsync("Could not resolve target path");
```

Output appears in **View → Output → Macros**. The same channel is used by the macro error renderer when a macro throws, so a user looking for "what went wrong with my macro" naturally finds your log lines too. See [`macro-debugging`](../macro-debugging/SKILL.md) for the full error-surface story.

## Pulling in a NuGet package

Add a `#r "nuget: PackageId, Version"` directive to reference any NuGet package. The Macros engine shells out to `dotnet build` to restore it on first run, then caches the result under `%LOCALAPPDATA%\Macros\NuGet\<hash>\`. Subsequent runs are zero-cost.

```csharp
#load ".intellisense/Macros.Intellisense.csx"
#r "nuget: Newtonsoft.Json, 13.0.3"

using Newtonsoft.Json;

var payload = new { macro = Context.MacroName, ts = DateTime.UtcNow };
await Log.InfoAsync(JsonConvert.SerializeObject(payload));
```

Constraints worth knowing:

- **Exact version pinning only.** No SemVer ranges. `13.0.3`, not `13.*`.
- **Net48 target.** The cache project targets `net48`; pick a TFM-compatible package.
- **VS host wins on shared assemblies.** If a package ships its own `Newtonsoft.Json` and Visual Studio has already loaded a different version, the host's version is used. This can produce surprising behaviour with packages that rely on a specific version of a runtime library.
- **First restore needs the .NET SDK on PATH.** The user is told via the status bar; subsequent runs work offline.

## Common patterns

### Run a VS command on the current file

```csharp
#load ".intellisense/Macros.Intellisense.csx"

await ExecuteCommandAsync("Edit.FormatDocument");
await ExecuteCommandAsync("File.SaveSelectedItems");
```

### Open a file and edit it

```csharp
#load ".intellisense/Macros.Intellisense.csx"

await OpenFileAsync(@"C:\Repos\MySolution\Notes.md");
await MoveCaretAsync(1, 1);
await TypeAsync($"# Notes — {DateTime.Now:yyyy-MM-dd}\n\n");
```

### Compose macros

```csharp
#load ".intellisense/Macros.Intellisense.csx"

await RunMacroAsync("format-on-save");
await RunMacroAsync("notify-team");
```

### Read selected text and uppercase it

```csharp
#load ".intellisense/Macros.Intellisense.csx"

var sel = DTE.ActiveDocument?.Selection as EnvDTE.TextSelection;
if (sel?.IsEmpty == false)
{
    sel.Insert(sel.Text.ToUpperInvariant(), (int)EnvDTE.vsInsertFlags.vsInsertFlagsInsertAtStart);
}
```

### Ask the user for input

```csharp
#load ".intellisense/Macros.Intellisense.csx"

string region = await PromptAsync("Region name", "MyRegion");
if (!string.IsNullOrWhiteSpace(region))
{
    await TypeAsync($"#region {region}\n\n#endregion\n");
}
```

## Anti-patterns — don't do these

| Don't | Why | Do instead |
|---|---|---|
| Delete the `#load ".intellisense/Macros.Intellisense.csx"` line. | The shim is the editor's only source of IntelliSense for `DTE`, `VS`, helper verbs. The runtime player intercepts and ignores it; deleting it doesn't change runtime behaviour. | Keep it. If IntelliSense is broken, that's a different problem — see [`macro-debugging`](../macro-debugging/SKILL.md). |
| Add `#r "EnvDTE"` / `#r "Macros.Engine"` / `using EnvDTE;` blocks. | The shim already supplies references and imports. Manual `#r`s for built-ins create version-skew warnings. | Trust the shim. Only add `#r "nuget: ..."` for external packages. |
| Wrap helper calls in `Task.Run(() => TypeAsync(...))`. | Helpers internally switch to the UI thread. Wrapping them in `Task.Run` defeats the purpose and introduces a thread hop the helper has to undo. | `await TypeAsync(...)` directly. |
| Skip `await` on a helper call. | Returns an unawaited `Task`. The next line runs before the previous one finishes. Causes intermittent failures that look like timing bugs. | Always `await`. |
| Use `Thread.Sleep(...)` to wait. | Blocks the calling thread, including the UI thread. | `await WaitAsync(milliseconds)`. |
| Recurse: a macro calls itself with `RunMacroAsync(myName)`. | Cycle detection throws `InvalidOperationException` at depth 1. Depth cap is 3. | Refactor the shared step into a third macro both call. |
| Introduce a class definition or `Main()` method. | The script host expects top-level statements. A class wraps your code in a way the player won't execute. | Top-level `await` only. |
